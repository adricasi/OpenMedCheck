## Request used (reuse in T-005)
`POST /api/chat`, `stream: false`, `keep_alive: "10m"`, messages = system prompt + one user
message, `format` = per-request JSON schema, and:

```json
{"think": false, "options": {"temperature": 0, "num_predict": 400}}
```

- `format` with a JSON schema works: 100% of 90+ responses were parseable JSON with the exact
  key set; enums (including a per-request `alternative_drug_id` enum and `null`) were honoured.
- **`think: false` is mandatory.** With the default thinking on, the 400-token budget is spent
  on reasoning and the content is empty (9/9 invalid, 0% valid, ~4.3 s). T-005 must send
  `think: false` (and must not rely on `num_predict` alone).
- The schema (per request): object with `status` (enum NO_ISSUE/WARNING/BLOCKED), `risk_level`
  (LOW..CRITICAL), `headline`, `rationale`, `renal_adjustment_required` (bool), `conflict_type`
  (enum incl. null), `alternative_drug_id` (enum of allowed alternatives + null), all required,
  `additionalProperties: false`. String length limits are checked by our validator, not by the
  schema.
- Draft prompt: `SYSTEM_PROMPT` (and optional `GUIDANCE`) in `scripts/spike_ollama.py`; the
  note is wrapped in `<untrusted_note>` tags and declared to be data, not instructions.

## Method
1 cold call (not counted), 3 warm-up calls (not counted), then 30 timed calls cycling over 9
synthetic contexts (3 A-like: suspected ACS only in the note, NSAID + home antiplatelet, rules
NO_ISSUE; 3 B-like: eGFR < 30 with a renally dosed antibiotic, rules WARNING; 3 C-like: benign
condition, normal renal function). Latency is the wall-clock time of the HTTP call (end to end
for the model step only; the rules step is not included). Validity is checked by our own strict
validator: exact keys, enums, types, headline <= 8 words, rationale <= 300 chars and <= 2
sentences, conflict_type present when status is not NO_ISSUE. First try only (no retry).
Percentiles: nearest-rank.

## Results (warm, `think: false`)

| Run | Prompt | Calls | Valid first try | p50 | p95 | max | Tokens out (mean) |
|---|---|---|---|---|---|---|---|
| 1 | draft (no clinical guidance) | 30 | 30/30 = 100% | 1.58 s | 1.73 s | 1.76 s | 102 |
| 2 | draft + `GUIDANCE` (`--guided`) | 30 | 30/30 = 100% | 1.34 s | 2.40 s | 2.94 s | 101 |

Cold first call after idle: 11.5 s on the very first run (model load), 2.0-3.4 s on later runs.
(Run 1 first execution, identical settings, gave p50 1.51 s / p95 1.68 s; it printed no verdict
tally, so the run above is the one with the tally.) Run 2 had two outliers (2.40 s, 2.94 s, both
on the first A1 calls after the prompt change); excluding them the rest were 1.22-1.55 s. They
are kept in the p95.

Verdict content (informational, from 30 calls each):

| Run | A-like (expect BLOCKED / ANTIPLATELET_ACS) | B-like (expect WARNING / RENAL) | C-like (expect NO_ISSUE) |
|---|---|---|---|
| 1 draft prompt | 0/12 (8x NO_ISSUE, 4x WARNING/GI_BLEED) | 9/9 | 9/9 |
| 2 with guidance | 12/12 (all BLOCKED/ANTIPLATELET_ACS) | 9/9 | 9/9 |

Thinking mode (`think: true`, run on 9 calls): 0/9 valid (content empty because the token budget
was consumed by reasoning), ~4.3 s. Not usable.

## Findings that matter beyond the budgets
1. **Preset-A-like detection depends on the prompt.** The unguided draft prompt got 0/12 on the
   "Gemma adds value" case (AC-003.4): the model returned NO_ISSUE or a GI_BLEED warning.
   Adding short conflict guidance (ANTIPLATELET_ACS and RENAL definitions) gave 12/12. This is
   not a tuned speed number, but note the guidance was written knowing the test cases and the
   three A-like cases are similar, so 12/12 is an optimistic indication, not evidence for
   AC-003.4 (>= 9/10 on the real preset). T-005/T-009 must evaluate the real preset A at
   temperature 0 and bump `PROMPT_VERSION`; the few-shot fallback of ADR 0004 is the next step if
   it falls short.
2. **`think: false` is required** (see above).
3. Output length is stable (~100 tokens), so latency is dominated by decode speed (~65-75 tok/s
   on this GPU) and is nearly constant across presets.
4. Not measured here: rules-card latency (no rules engine yet), the 10 s total-deadline
   behaviour, retry-on-invalid (never needed), AC-003.5 content checks (dose patterns, other
   drug names, banned words) on model text, and adversarial/injection notes.

## Reproduce
```bash
python3 scripts/spike_ollama.py --calls 30            # draft prompt
python3 scripts/spike_ollama.py --calls 30 --guided   # with conflict guidance
python3 scripts/spike_ollama.py --calls 9 --warmup 1 --think --guided   # thinking mode (fails)
```
