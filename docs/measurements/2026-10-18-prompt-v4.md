# Model eval: English presets and prompt v4 (2026-10-18)

Spec: AC-003.4, AC-009.1, AC-009.2, NFR-004, NFR-012. Scripts: `scripts/eval_model.py` (real
`OllamaClient` through `check_service.final_card`) and `scripts/measure.py` (end to end over
HTTP). Aggregates only; no patient context or model text. Presets are synthetic.

## What changed and why
The presets' reasons for consult and ED notes were translated from Spanish to English, and the
Spanish brand name of aspirin became "aspirin" (product.md A-1). Preset A's note now reads "64-year-old man
with a 2-hour history of crushing central chest pain radiating to the left arm, with
diaphoresis. Suspected ACS; ECG and troponin pending. On daily aspirin."

On prompt v3 a first English wording of the note ("... with sweating. ... Takes aspirin daily.")
broke AC-009.2: preset A re-checked with paracetamol (A-alt) gave
`BLOCKED / ANTIPLATELET_ACS` in **15/15** calls (the Spanish note had given `NO_ISSUE` 15/15).
An intermediate prompt that only added the drug class to the order line ("NSAID: no") still
blocked A-alt 15/15, and in a scratch probe it also blocked A-alt with the old Spanish note.
Conclusion: whenever the ANTIPLATELET_ACS guidance is in the prompt, Gemma tends to attach the
conflict to whatever drug is ordered; the language of the note was not the real cause.

| | ANTIPLATELET_ACS guidance |
|---|---|
| v3 | One text for every order: "applies only when ALL three hold: (1) the proposed drug is an NSAID, (2) ... (3) ... If the proposed drug is not an NSAID (for example paracetamol), never report ANTIPLATELET_ACS ..." |
| v4 | Whether the order is an NSAID comes from the drug list, so the prompt carries only the matching text. NSAID order: "the proposed drug is an NSAID. Report this conflict only when BOTH hold: ... suggests an acute coronary syndrome ... AND the patient takes an antiplatelet ...". Any other order: "ANTIPLATELET_ACS does not apply: the proposed drug is not an NSAID. Never report it ... For this order a suspected ACS or a home antiplatelet is not an ANTIPLATELET_ACS conflict; still report any other conflict the context supports." (The last clause came from the safety review: an earlier v4 draft said these were "not a conflict" at all, which could have discouraged other note-only conflicts.) An unknown drug ID raises, which check_service turns into the rules-only card. The order line also names the drug class. "SCA" was removed from the guidance. |

RENAL guidance, request options, schema, untrusted-note structure and the combiner are
unchanged. Scratch probe on v4 (one call each, not committed): dexketoprofen `BLOCKED` and
paracetamol `NO_ISSUE` for the first English note, that note without its aspirin sentence, "On
aspirin at home", and the old Spanish note. The numbers below are from the final v4 text and the
final preset A note.

## Environment
`gemma4:e4b` (digest dc35e8d9c606), Ollama 0.35.1, NVIDIA RTX 3000 Ada Generation Laptop GPU
(8188 MiB), `think: false`, temperature 0, `num_predict 400`, JSON-schema format, 10 s deadline,
1 retry; code at `f414909` plus this change. `eval_model.py`: 3 warm-up calls, then 60 timed calls
cycling A, A-alt, B, C (15 each); latency is the model step. `measure.py`: 200 rules calls,
40 final calls (10 per case), then a cold start after unloading the model.

## Caveats
1. Temperature 0 makes repeated calls on one fixed case nearly deterministic: the runs show
   stability, not robustness to other wordings. Only paracetamol was measured as the non-NSAID
   order with preset A's patient.
2. The v4 fix moves part of the decision (is the order an NSAID?) from the model to the drug
   list. The model still reads the note for the ACS; that is the part only it can do.
3. The cold start was faster than on 2026-10-17 (6.9 s vs 10.0 s); one sample, and model load
   time depends on the machine's state.

## Reproduce
```bash
uv run python scripts/eval_model.py --calls 60 --warmup 3
uv run python scripts/measure.py --calls 40 --rules-calls 200 --cold-start
uv run pytest -m ollama
```
