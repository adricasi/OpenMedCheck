# Model eval: prompt v3 (ANTIPLATELET_ACS guidance fix) (2026-10-17)

Spec: AC-003.4, AC-009.1, AC-009.2, NFR-004, NFR-012. Task: T-007 run-through finding
(`docs/ui-checklist.md`). Script: `scripts/eval_model.py` (real `OllamaClient` through
`check_service.final_card`; aggregates only, no context or model text). Presets are synthetic.

## Bug and fix
Re-checking preset A with the alternative paracetamol returned BLOCKED (rationale "The proposed
drug is an NSAID") in 6/6 manual runs on prompt v2. Cause: the v2 guidance read "... and the
proposed order is an NSAID, **or** the patient takes an antiplatelet", so a home antiplatelet
alone triggered the conflict for any drug.

| | Guidance text |
|---|---|
| v2 | `ANTIPLATELET_ACS: the note suggests an acute coronary syndrome (chest pain, suspected ACS or SCA) and the proposed order is an NSAID, or the patient takes an antiplatelet such as aspirin or clopidogrel. ... Use BLOCKED, tier HIGH.` |
| v3 | `ANTIPLATELET_ACS applies only when ALL three hold: (1) the proposed drug is an NSAID, (2) the note suggests an acute coronary syndrome ... and (3) the patient takes an antiplatelet such as aspirin or clopidogrel. ... A home antiplatelet or a suspected ACS alone is not a conflict. If the proposed drug is not an NSAID (for example paracetamol), never report ANTIPLATELET_ACS and do not call the proposed drug an NSAID.` |

This matches the rule table's `NSAID_ANTIPLATELET_ACS` (NSAID class + ACS diagnosis + chronic
antiplatelet), except that the model reads ACS from the note instead of a coded diagnosis. RENAL
guidance had no and/or bug; "and" was capitalised ("AND the proposed drug needs renal adjustment")
for clarity. There is no GI_BLEED guidance. Request options, schema and the untrusted-note
structure are unchanged.

## Environment
Same as the v2 measurement: `gemma4:e4b`, `think: false`, temperature 0, `num_predict 400`,
JSON-schema format, 10 s deadline, 1 retry; Ollama at `http://127.0.0.1:11434`, model already
loaded. 3 warm-up calls, then 60 timed `final_card` calls cycling A, A-alt, B, C (15 each).
A-alt = preset A's patient and note with order paracetamol, PO, 1 g every 8 hours (dose text is
not sent to the model). Latency is the model step (`ModelResult.latency_ms`), nearest-rank
percentiles. Prompt v3 only (one version tried; no iteration needed).

## Caveats
1. Temperature 0 makes repeated calls on one fixed case nearly deterministic: the 15 runs per case
   show stability, not robustness to rewording. The fix is shown for one note and one alternative
   (paracetamol); other non-NSAID orders with the same patient were not measured.
2. A-alt is measured with the real model, but the escalate-only combiner still means any model
   mistake on a non-NSAID can only add a warning, never remove a rules finding.
3. Not measured: cold start, injection notes, `pytest -m ollama`.
