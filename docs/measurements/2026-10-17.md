# End-to-end measurement (T-009), 2026-10-17

Spec: REQ-012, AC-003.4, AC-009.2, NFR-004, NFR-012, REQ-014. Base commit `e6e5f84` (prompt
`PROMPT_VERSION` 3). Scripts: `scripts/measure.py` (HTTP, client-side timings),
`scripts/eval_model.py` (first-try validity), `uv run pytest -m ollama`. Presets are synthetic;
only aggregates are recorded.

## Environment
- GPU: NVIDIA RTX 3000 Ada Generation Laptop GPU, 8188 MiB, driver 617.14 (WSL2); model 100% in VRAM
- Ollama 0.35.1; model `gemma4:e4b`, digest `dc35e8d9c606`, 6.6 GB
- Request options unchanged: `think: false`, temperature 0, `num_predict` 400, JSON-schema
  format, 10 s total deadline with one retry

## Method
`scripts/measure.py` starts `python -m openmedcheck` on a free loopback port and calls it over
HTTP with httpx. Order: `GET /api/model/health` -> `POST /api/model/warmup` -> poll health until
`ready` -> 200 timed `POST /api/check/rules` calls -> 40 timed `POST /api/check` calls cycling A,
A-alt (preset A's patient with paracetamol ordered), B, C (10 each) -> cold start. Times are
wall-clock at the client including JSON (de)serialisation; nearest-rank percentiles. "Valid"
here means the card has `source = rules+model` (valid on the first try or after the retry).

## Warm-up (REQ-014, T-008) against real Ollama: confirmed
Model unloaded at start. `/api/model/health` returned `warming`; `POST /api/model/warmup` returned
202 `{"status":"warming"}`; health became `ready` after 12.9 s and `/api/ps` listed
`gemma4:e4b` 100% in VRAM. The timed calls that followed were warm.

## Cold start (honest miss of the 10 s deadline)
After `keep_alive: 0` on `gemma4:e4b` only (no other model touched), the first `/api/check`
without warm-up took **10012 ms** and returned a **rules-only card** (`source = rules`): loading
the model took longer than the 10 s model deadline, so the fail-safe (REQ-005) fired as
designed. The next call took 1858 ms with `source = rules+model`. A cold first call is therefore
slower than the 3 s budget (which NFR-004 states for warm calls) and loses the model's reading
for that one call; cause: model load time on this laptop GPU (about 13 s to `ready`, see
warm-up). Mitigation is the warm-up endpoint, which the UI calls on page load. One cold sample
only (n=1).

## Verdicts
- NFR-004 rules card p95 < 200 ms: met (3.8 ms).
- NFR-004 final card p95 < 3 s warm: met (1.72 s). Cold start is outside the stated budget and
  exceeds the 10 s deadline on this machine (above).
- NFR-012 >= 95% valid first try: met (60/60 first try; 40/40 end to end).

## Caveats
1. Temperature 0 makes repeated calls on one fixed case nearly deterministic; 100% shows
   stability on four cases, not robustness to other notes.
2. Single machine, 8 GB laptop GPU, one session; other GPU load was not controlled.
3. Over HTTP the first-try rate is not observable; it comes from `eval_model.py`.
4. The integration tests assert only the >= 9/10 thresholds, not the exact pass counts.
