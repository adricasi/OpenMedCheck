# Model eval: note findings with evidence quotes, prompt v5 (2026-10-18)

Spec: AC-003.4, AC-003.6, AC-003.7, AC-009.2, NFR-004, NFR-012; task T-013; ADR 0006.
Scripts: `scripts/eval_model.py` (real `OllamaClient` through `check_service.final_card`) and
`scripts/measure.py` (end to end over HTTP). Aggregates only; no model output in this file, and
the only note text quoted is from the synthetic presets.

## What changed
Gemma now also answers four note questions, each with a quote copied from the ED note or the
reason for consult: `note_acs_quote` and `note_gi_bleed_quote` (a phrase or null),
`note_medications` and `note_allergies` (short lists of known drug or class IDs with quotes). The
code keeps a finding only if its code is valid and its quote appears word for word in the note,
adds the kept findings to the coded context and runs the rules again. Rules that fire only
because of a finding show the quote on the card ("From the ED note"). The v4 guidance and the
model's own escalate-only verdict stay, but for the conflicts the rules decide (ANTIPLATELET_ACS,
GI_BLEED, ALLERGY) the model's own escalation counts only if a rule of that type fired (AC-003.8).
The verifier also requires the quote to name what it is coded as and drops findings whose sentence
denies them or gives only past history; it keeps at most 8 findings and shows the note's own
words. `num_predict` 400 → 600.

### First design, rejected
A single free list (`note_findings` with kind, code and quote) was tried first (60 calls):
preset B's "Suspected urinary tract infection" was coded `ACS` in 15/15 calls, because the only
condition codes were ACS and GI bleed; preset C returned 4 filler findings with the quote "none"
in every call (all dropped, model step p95 3.58 s, over budget); "On daily aspirin" came back as
the class `ANTIPLATELET` (dropped). A verbatim quote proves the words exist, not that they mean
the code. Asking one question per condition (a quote or null) fixed all three: B and C returned
no findings, aspirin came back as `aspirin`.

## Environment
`gemma4:e4b` (digest dc35e8d9c606), Ollama 0.35.1, NVIDIA RTX 3000 Ada Generation Laptop GPU
(8188 MiB), `think: false`, temperature 0, `num_predict 600`, JSON-schema format, 10 s deadline,
1 retry. `eval_model.py`: 3 warm-up calls, then 105 timed calls cycling seven cases (15 each):
A, A-alt (A with paracetamol), B, C, two note-only variants, **D-note** (template D with the coded
GI bleed removed: the bleed is only in the note) and **E-note** (template E with the recorded
allergy removed: "Penicillin allergy (rash) in the record." is only in the note), and **A-neg**
(preset A's patient with "ACS ruled out: ECG and troponin normal. No GI bleeding. On daily
aspirin.").

A-neg before the gate (AC-003.8): the verifier already dropped the ACS answer, but the model's own
verdict (ANTIPLATELET_ACS) still blocked the NSAID in 15/15 runs. With the gate the card is
NO_ISSUE 15/15; the model's escalation is set aside and logged as `model_escalation_gated`.

End to end (`measure.py`, 40 final calls over A, A-alt, B, C): rules card p95 1.4 ms; final card
p50 1.84 s, p95 2.26 s, max 2.31 s; statuses A BLOCKED 10/10, A-alt NO_ISSUE 10/10, B WARNING
10/10, C NO_ISSUE 10/10; 40/40 cards from rules+model; cold start 7.59 s with the model's reading.
`pytest -m ollama`: 2 passed.

After the safety review the negation check was made local to the matched term (a sentence-wide
check dropped real findings such as "Suspected ACS, no ST elevation"). A re-run of all 105 calls
gave identical outcomes for all seven cases, 105/105 valid, model-step p95 at most 2.30 s.

### A run with timeouts
An earlier 90-call run of the same code had 25 timeouts spread evenly over all six cases,
including B and C, which return almost nothing. A raw probe straight after (18 calls cycling the
cases) was 1.3–2.1 s each with identical token counts, and the repeat run above had no timeout.
The GPU read 84 °C after the runs; thermal throttling is the likely cause, not proven. A timeout
falls back to the rules-only card (REQ-005), so the cost is a lost model reading, not an error.

## Caveats
1. Six fixed notes at temperature 0 show stability, not robustness to other wordings, other
   languages or real records.
2. The model's own conflict label was sometimes wrong (D-note: `ANTIPLATELET_ACS` for a GI
   bleed). The card used the rules' text and the rules' alternative there, because the rules
   decided the status at a higher tier; the label is not shown.
3. The verbatim check cannot tell whether a real phrase means the code it was given; the first
   design showed this. Per-question fields reduce it; specialist review and a larger evaluation
   set are needed before relying on it.
4. Extraction costs about 0.8 s per check (p95 1.45 s → 2.26 s). The timeout run above is an
   open risk: under throttling a check falls back to rules only and loses a note-only BLOCKED.
5. Only one negated note was measured; other negations, past-history wording and the 8-finding
   cap are covered by unit tests, not by the real model.
6. With AC-003.8, a finding the model fails to extract also loses its own escalation for the
   rule-decided conflicts. Extraction found every expected finding in these runs.
